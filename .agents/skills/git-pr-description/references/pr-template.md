## 📦 切換 branch 後需執行的指令

<!--
產生條件：PR 含有下列任一變更時必須產生此區塊，否則整段省略——
- lockfile / package.json 相依變動（需重新 install）
- codegen 產物不進版控（如 prisma generate、protobuf、GraphQL codegen）
- 新增 DB migration
- 新增 / 改名環境變數
- docker / infra 設定變更

規則：
- 指令依執行順序放在同一個 bash code block，每條指令以註解標明原因
- code block 下方以 bullets 補充：漏跑的具體症狀（錯誤訊息）、不需要跑的指令、切回舊 branch 是否需要額外動作
- 新增環境變數時列出 key 與範例值位置（如 .env.example），不可寫出真實 secret
-->

依序執行：

```bash
npm install                  # lockfile 變動，須重裝相依
npm run <codegen-script>     # 產物不進版控，漏跑會無法啟動
```

- 漏跑 codegen 的症狀：啟動時報 `ERR_MODULE_NOT_FOUND ...`
- 不需要跑 `<其他指令>`：說明原因
- 切回舊 branch 時：說明是否需要重跑 install / generate


## 🧪 測試步驟

<!-- 
  規則：
  - 必須為「修改的內容」中的每一個模組 / 元件都產生至少一個對應的測試案例
  - 確保所有變更皆被涵蓋，不可遺漏
  - 依變更範圍分為「後端測試」、「前端測試」、「CI / Infra 測試」三大區塊，僅產生實際涉及的區塊
  - CI workflow、建置設定、開發工具鏈等不屬於前後端程式碼的變更，一律歸入「CI / Infra 測試」
  - CI / Infra 測試中，同一次操作可驗證多個變更點時合併為單一案例，驗證點列在預期結果中分點呈現
  
  後端測試案例需包含：
  1. 呼叫的 API endpoint（含 HTTP method）
  2. 關鍵請求參數摘要
  3. 操作步驟（step by step）
  4. 預期回傳格式（JSON 結構示意）
  5. 預期結果
  
  前端測試案例需包含：
  1. 操作步驟（step by step）
  2. 預期結果
  3. 依測試類型決定是否附截圖提示：
     - 單元測試（以 Vitest / Jest 指令執行，如 vitest run、jest）：不需截圖，步驟以「執行指令 + 預期結果」呈現即可
     - 手動 / E2E 測試（需在瀏覽器操作頁面）：末尾附上「📎 請附上截圖示意」提醒
-->

### 後端測試

#### 測試案例 BE-1：[API / 模組 A 的測試情境]

- **API**：`METHOD /api/path`
- **參數摘要**：簡述關鍵請求參數
- **操作步驟**：
  1. 步驟一
  2. 步驟二
- **預期回傳格式**：
  ```json
  {
    "code": 0,
    "data": { "key": "value" }
  }
  ```
- **預期結果**：描述預期行為
